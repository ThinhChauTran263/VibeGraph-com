Import Local Folder

Phân tích một thư mục Java đang nằm trên máy chạy VibeGraph. Ưu điểm: bật được theo dõi realtime — graph tự cập nhật khi sửa file, không cần nén zip.

Mục tiêu review

  • Nhập đường dẫn hợp lệ → import chạy, tiến độ hiển thị, kết thúc mở graph.
  • Nút Browse mở Directory Browser để chọn thư mục.
  • Xử lý lỗi rõ ràng: đường dẫn sai, ngoài thư mục cho phép, backend chưa chạy.

Tiền điều kiện

Neo4j + Backend + Web client đều chạy. Nếu backend cấu hình vibegraph.projects.allowed-root thì đường dẫn phải nằm trong thư mục đó.

Kịch bản thao tác

# Thao tác Kết quả kỳ vọng P/F
1 Vào /dashboard, tab "Local folder" Form hiện ô "Project folder path", nút Browse, ô "Display name (optional)".
2 Bấm Browse… Directory Browser Modal mở, duyệt được ổ đĩa/thư mục, chọn được 1 thư mục.
3 Chọn thư mục dự án Java, đặt tên hiển thị, bấm Import folder Trạng thái chuyển "importing", có tiến độ %.
4 Chờ phân tích xong Tự điều hướng sang /projects/:id/graph, graph hiển thị.
5 Nhập đường dẫn không tồn tại rồi Import Thông báo lỗi rõ ràng (path/not found), không treo.
6 Tắt backend rồi Import Báo "Cannot reach the server…".
Lưu ý bảo mật: API duyệt thư mục (/api/projects/browse) đọc hệ thống file của máy chủ. Review cần xác nhận có giới hạn allowed-root khi triển khai thật, tránh lộ toàn bộ ổ đĩa.

Tham số & ràng buộc cụ thể

Tham số (env) Mặc định Ý nghĩa
IMPORT_POLL_INTERVAL_MS 1000ms Nhịp poll trạng thái project khi WebSocket không đủ.
IMPORT_STALL_TIMEOUT_MS 300000ms (5 phút) Chỉ bỏ cuộc khi không tiến triển suốt khoảng này (stall thật).
IMPORT_ABSOLUTE_TIMEOUT_MS 3600000ms (1 giờ) Trần tuyệt đối chống poll vô hạn.
vibegraph.projects.allowed-root (trống) Nếu đặt: đường dẫn phải nằm trong thư mục này.

Tiến độ ưu tiên qua STOMP topic /topic/projects/{id}/status; poll là fallback. Chỉ thông báo lỗi khớp mẫu an toàn (required / directory / path / allowed / not found / taking longer…) mới hiển thị nguyên văn, còn lại rơi về thông điệp chung.

Ngóc ngách backend & bảo mật

  • Chạy nền: POST /import-local trả 202 ngay; phân tích chạy trên analysisExecutor (ThreadPool core 2 / max 4 / queue 50). Bão hoà → RejectedExecutionException → project FAILED → 503.
  • Trạng thái: CREATED → ANALYZING → ANALYZED / FAILED (progress 0..100), lưu in-memory (ConcurrentHashMap) + khôi phục từ Neo4j sau restart.
  • allowed-root: validateRootPath dùng toRealPath() + phải là directory; nếu vibegraph.projects.allowed-root đặt thì path phải nằm trong. Mặc định trống → KHÔNG giới hạn.
  • Sau ANALYZED: watchProject theo dõi thư mục thật của user (chỉ luồng local).
Bảo mật (CRITICAL cho deploy): Không có auth trên bất kỳ controller/WebSocket nào. Với allowed-root trống, /browse liệt kê ổ đĩa & mọi thư mục, /import-local import bất kỳ thư mục host → lộ source qua graph/source tools. Review phải yêu cầu đặt allowed-root ở môi trường thật. Ngoài ra: analyze/delete không có lock → analyze trùng có thể interleave; deleteFile không transaction.

Điểm cần soi

  • Tiến độ không "đứng hình": có cơ chế timeout khi stall + timeout tuyệt đối.
  • Nếu poll tiến độ bị rớt, project vẫn xuất hiện ở danh sách và tự chuyển ANALYZED.
  • Thông báo lỗi được lọc an toàn (không lộ stack trace nội bộ).

Luồng hoạt động của code

  • UI: ImportProjectPanel.vue (tab) → AddProjectLocal.vue (form + nút Browse mở DirectoryBrowserModal.vue).
  • Composable: useLocalImport.ts gọi importApi.importLocal() rồi theo dõi tiến độ qua STOMP (useWebSocket.ts) kết hợp poll trạng thái (projectApi), có STALL + ABSOLUTE timeout.
  • HTTP: lib/api.ts → POST /api/projects/import-local và GET /api/projects/browse?path=.
  • Backend: LocalProjectController nhận request → LocalImportService (module graph/importer) chạy phân tích nền; tiến độ phát qua topic /topic/projects/{id}/status.
  • Phân tích: parser (parser/service + parser/visitor/*) dựng node/edge → lưu Neo4j (graph/repository).
  • Kết thúc: FE điều hướng sang route graph với projectId trả về; lưu vào stores/project.ts.

Phạm vi triển khai & định hướng (để trình bày hội đồng)

Định vị 1 câu: Local folder là chế độ same-host / môi trường phát triển — backend và mã nguồn cùng máy, nên là luồng DUY NHẤT có realtime (graph tự cập nhật khi lập trình viên code). Archive & GitHub là luồng onboarding cho bản deploy.

"local" = local với MÁY CHỦ, không phải máy người dùng

  • /browse chạy listRoots() trên host backend; picker liệt kê ổ đĩa của server (chạy local thì trùng máy bạn nên trông như "ổ user"). Trình duyệt web không được phép tự duyệt ổ đĩa máy user.
  • Deploy đa người dùng: user gõ path máy họ → 400 (server không có path đó); còn browse ổ server là lộ filesystem. Vì vậy bản deploy nên tắt/thay picker này.

Bảng định vị 3 luồng import

Luồng Dùng khi Realtime? Production đa user?
Local folder Chạy same-host / dev; demo realtime ✅ (khi code sống & sửa trên host) Chưa (dev/self-hosted; xem roadmap)
Archive (zip) Đưa dự án bất kỳ lên một lần ❌ (snapshot) ✅
GitHub Repo public, không setup ❌ (snapshot) ✅

Câu trả lời gợi ý khi hội đồng hỏi "deploy có chạy cho user từ xa không?"

"Không, vì 'local' là local với máy chủ, không phải máy người dùng, và trình duyệt không được tự duyệt ổ đĩa của user. Trên bản deploy, luồng cho người dùng cuối là Archive/GitHub; còn Local realtime sẽ mở rộng đa người dùng ở hướng phát triển."

Định hướng multi-user (future work)

  • Chọn folder từ máy user bằng folder picker của trình duyệt (webkitdirectory / File System Access API) hoặc CLI push (xác thực bằng API key) — đẩy file qua HTTPS, không cần zip, hỗ trợ delta.
  • Sandbox theo user: <storage-root>/<userId>/<projectId>; mọi thao tác khóa trong subtree, chặn ../symlink/path tuyệt đối.
  • Ownership check mọi API có projectId: project.ownerId == currentUser (lưu ở Postgres) → chống user A đọc project user B (chống IDOR). Sandbox chỉ khóa file; check này khóa cả API graph/source/impact.
  • Hạn ngạch dung lượng/user (vd 200MB–2GB tùy plan) + cap số file; chỉ nhận .java; quota check trước khi ghi (413 khi vượt).
  • Cập nhật: sau mỗi push → watcher bắt (sửa nhỏ) hoặc gọi /analyze (đẩy batch, index lại sạch). Không chạy song song watcher + analyze cùng project (tránh race).
  • Kênh: HTTPS + token (git-over-HTTPS / CLI), không cấp SSH shell cho web user; key để ở header, lưu hash, revoke + rate-limit.

Ghi chú: VibeGraph chỉ parse (đọc AST), không biên dịch/chạy code của user → nội dung code không phải vector RCE; rủi ro chính là access-control/traversal/DoS/quyền riêng tư dữ liệu.
