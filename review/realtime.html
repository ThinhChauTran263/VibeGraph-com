Realtime Update — Graph tự cập nhật khi sửa file

Với project import kiểu Local folder, backend theo dõi file (file watcher) và phát sự kiện qua WebSocket/STOMP. Client vá graph tại chỗ (không dựng lại toàn bộ) nên camera/zoom/layout được giữ nguyên.

Mục tiêu review

  • Sửa/thêm/xóa file Java trong project local → graph phản ánh thay đổi gần realtime.
  • Patch tại chỗ: thêm class chỉ chèn node mới; xóa file chỉ bỏ node liên quan.
  • Camera/zoom không bị reset khi có cập nhật.

Tiền điều kiện

Project được import bằng Local folder (watcher bật: vibegraph.watcher.enabled=true), đang mở tab Graph của project đó. Sửa file .java trong thư mục nguồn.

INCREMENTAL → vá tại chỗ (giữ camera nhờ cờ skipNextRebuild). FULL_UPDATE → dựng lại graph. Sự kiện của project khác project đang xem bị bỏ (stale-guard theo projectId).

Thuật toán FULL_UPDATE vs INCREMENTAL (backend)

  • Chọn loại (FileChangeBroadcaster.onFileChange): nếu project root không có trong projectRoots (watch chưa khởi động qua watchProject) → FULL_UPDATE (getFullGraph, có cap payload). Ngược lại → INCREMENTAL.
  • Diff INCREMENTAL: snapshot before = getFullGraph → deleteFile(projectId, path) → nếu CREATE/MODIFY thì parse lại đúng 1 file (parserService.parseFile) & upsert → snapshot after.
  • added = node mới/thuộc file đổi + edge mới/chạm node đó; removed = id có before mà mất after. modified luôn null.
  • Watch chỉ bật sau ANALYZED (watchProject) hoặc ProjectRewatchRunner lúc khởi động. Archive/GitHub watch bản copy trong tmp workspace; chỉ local watch thư mục thật của user.
Ngóc ngách reviewer: INCREMENTAL không được cap (chỉ FULL_UPDATE cap) → 1 file đổi tạo diff lớn thì payload socket không giới hạn. Diff là chuỗi thao tác không nguyên tử (before → delete → reparse → after); một thay đổi/analyze xen giữa 2 snapshot có thể cho diff sai. deleteFile chạy 2 câu Cypher auto-commit riêng (không transaction). parseFile đơn lẻ resolve hạn chế (CALLS cross-class có thể thiếu so với full analyze).

Điểm cần soi

  • Patch INCREMENTAL không reset camera (cờ skipNextRebuild).
  • Payload được validate ở biên; payload lỗi không làm hỏng store.
  • Stale-guard: sự kiện của project cũ không áp lên project đang xem.
  • Debounce watcher (vibegraph.watcher.debounce-ms) tránh bão sự kiện khi lưu liên tục.

Luồng hoạt động của code

  • Backend watcher: module watcher/service theo dõi file → graph/websocket/FileChangeBroadcaster phát sự kiện FULL_UPDATE/INCREMENTAL lên STOMP topic.
  • FE nhận: composables/useGraphRealtime.ts (dùng useWebSocket.ts) subscribe topic, validate bằng lib/graphPatch.ts (parseGraphUpdateEvent), vá store immutably (applyGraphUpdate).
  • Vá canvas tại chỗ: callback onPatched → GraphCanvas.patchSigmaIncremental thêm/bớt node&edge trực tiếp trên Graphology graph, đặt skipNextRebuild để watcher filteredGraphData không dựng lại (giữ camera).
  • Đồng bộ phái sinh: bumpGraphVersion() để cache diagram revalidate.
