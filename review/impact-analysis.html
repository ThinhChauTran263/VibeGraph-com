Impact Analysis — Phân tích blast radius

Panel bên phải (dưới Node Detail). Chọn 1 node → ước tính "bán kính ảnh hưởng" nếu thay đổi node đó. Panel có 2 dropdown (Profile, Depth) + nút Analyze; kết quả gồm risk badge, 2 số đếm (Direct/Total) và 3 nhóm node theo độ sâu.

Panel có những gì — và chọn thì ra sao

Bố cục cố định: Profile · Depth · nút Analyze. Vùng kết quả bên dưới cuộn riêng (Analyze luôn với tới được).

① Dropdown "Profile" — 3 lựa chọn

Mỗi profile định nghĩa tập loại quan hệ được duyệt và hướng duyệt (nguồn: graph/model/ImpactProfile.java).

Option (label)apiValueQuan hệ duyệtHướngÝ nghĩa khi chọn
Dependency
(mặc định cho node code)		 dependency CALLS · IMPORTS · EXTENDS · IMPLEMENTS · INJECTS ngược về target
(ai phụ thuộc node này)		 "Nếu sửa/xóa node này thì cái gì gãy?" — gồm caller, importer, lớp con, lớp hiện thực, bean tiêm nó.
Structural structural CONTAINS · DEFINES · HAS_METHOD · HAS_FIELD · HANDLES_ROUTE xuôi từ target Node này "chứa/định nghĩa" gì: package→file→class→method/field, controller→route. Hợp với node lớn (File/Package/Class).
Type/Data-flow type-data-flow TYPE_OF · PARAMETER_TYPE · RETURNS · READS · WRITES · CATCHES · STEP_IN_FLOW xuôi từ target Liên kết kiểu + luồng dữ liệu sâu (CPG). READS/WRITES/CATCHES chỉ có khi backend bật deep-CPG.

Dòng trợ giúp dưới form đổi theo profile: dependency = "Calls, imports, inheritance and injection dependents."; structural = "Containment, definitions, fields, methods and route handlers."; type-data-flow = "Type links plus deep CPG reads, writes, catches and flow steps."

② Dropdown "Depth" — 4 lựa chọn: 1, 2, 3, 5

Giá trị hợp lệ cố định IMPACT_ALLOWED_DEPTHS = [1,2,3,5] (mặc định 1). Độ sâu = số bước traversal tối đa từ node target. Kết quả trả về được nhóm theo bậc:

Bậc (d)Nhóm (dependency)Nhóm (profile khác)Nghĩa
d = 1Will breakDirect relatedPhụ thuộc trực tiếp — sẽ gãy. Dùng để tính risk & số "Direct".
d = 2Likely affectedIndirect relatedGián tiếp — nhiều khả năng ảnh hưởng.
d ≥ 3May need testingFurther relatedBắc cầu — nên kiểm thử (gộp mọi bậc ≥3).

Chọn depth = 1 chỉ thấy nhóm "Will break". Chọn 5 gộp d≥3 vào "May need testing". Nhóm rỗng sẽ bị ẩn.

③ Nút Analyze & kết quả

  • Risk badge (màu theo mức) tính từ số Direct dependents (d=1) — không phải tổng.
  • Direct = số node phụ thuộc trực tiếp: đường ngắn nhất tới target đúng 1 hop (trỏ thẳng qua 1 cạnh CALLS/IMPORTS/EXTENDS/IMPLEMENTS/INJECTS). Đây là số dùng để tính Risk.
  • Total = tổng số node phụ thuộc phân biệt trong phạm vi Depth đã chọn (mọi bậc 1..maxDepth). Vì mỗi node đếm đúng 1 lần theo bậc ngắn nhất (min(length(path))), các bậc không chồng lấn nên Total = Direct(d1) + d2 + d3 + ….
  • Total phụ thuộc Depth: depth=1 → Total = Direct; depth=3 → Total = d1+d2+d3; depth=5 → tới d5. Total là số đếm THẬT (không cap) nên có thể lớn hơn số node được liệt kê (danh sách cap 50/bậc).
  • Mỗi node ảnh hưởng: bấm tên → điều hướng & center node đó trên canvas (emit select); nút { } → mở Code Viewer (chỉ hiện khi node có filePath và không thuộc Package/Project/External).
Ví dụ cụ thể — sửa OrderService.save(), chọn Depth = 2:
  • OrderController.create() & update() gọi thẳng save() → Direct = 2 (bậc d=1, nhóm "Will break").
  • 3 nơi khác gọi 2 controller đó (không gọi thẳng save) → d=2 = 3 (nhóm "Likely affected").
  • Total = 5 (2 + 3). Risk tính theo Direct = 2 → LOW.
  • Nếu một node vừa tới được ở d=1 vừa ở d=2, nó chỉ được đếm ở d=1 (bậc nhỏ nhất) — không tính 2 lần.

Hành vi tự động & ràng buộc (quan trọng khi review)

  • Tự chọn profile theo loại node: khi chọn node thuộc Class, Interface, Enum, Record, DBModel, Annotation, Method, Constructor, External → mặc định dependency. Các loại khác (File, Package, Project, APIEndpoint, Field, LocalVariable, Route) → tự đổi sang structural (để Analyze không ra rỗng ngay).
  • Đổi Depth hoặc Profile sau khi có kết quả → invalidate (panel reset), buộc bấm Analyze lại → tránh số liệu "lệch" với lựa chọn hiện tại.
  • Đổi node đang chọn → reset kết quả + đặt lại profile theo loại node mới.
  • Chống race: mỗi request có token đơn điệu; kết quả cũ đến muộn không ghi đè kết quả mới.
  • Sau khi chạy xong, panel tự cuộn kết quả vào tầm nhìn (tránh cảm giác "bấm không thấy gì").

Trạng thái rỗng — 3 thông điệp khác nhau

Tình huốngThông điệp
Profile dependency + node không phải target hợp lệGiải thích rỗng là đúng cấu trúc, gợi ý chọn Class/Interface/Method.
Profile dependency + target hợp lệ nhưng không ai phụ thuộc"Nothing depends on X … thường gặp với controller/route entrypoint."
Profile khác + không có quan hệ"No {profile} relationships found … within depth N."

Chi tiết Cypher & ngóc ngách backend (reviewer soi kỹ)

  • Cách tính depth: Cypher MATCH path=(dependent)-[:pattern*1..maxDepth]->(target), depth = min(length(path)) — mỗi dependent gán về bậc ngắn nhất.
  • Chiều mũi tên: profile dependency directedToTarget=true → (dependent)-[...]->(target) (ai trỏ TỚI target = dependents); structural/type-data-flow =false → cạnh vô hướng -[...]- (duyệt 2 chiều).
  • counts ≠ nodes: danh sách node cap 50/bậc (MAX_IMPACT_NODES_PER_DEPTH); nhưng count KHÔNG cap → Direct/Total phản ánh số thật. Vd d=1 có 200 dependents: Direct=200 nhưng "Will break" chỉ liệt kê 50.
  • mayNeedTesting (d≥3) cap 50 tổng cộng (không phải 50/bậc).
  • 2 lượt traversal riêng cho nodes & counts → chi phí gấp đôi trên hub node (điểm hiệu năng cần soi; counts không LIMIT).
⚠ Doc/behavior & API cần lưu ý:
  • Javadoc ImpactAnalysisResponse ghi "HIGH: … OR critical path" nhưng không có logic critical path — risk thuần theo count d=1.
  • Endpoint /impact default depth ở controller = 3 (còn UI luôn gửi 1). Validate {1,2,3,5} ở service; sai → 400.
  • Project chưa analyze → target node không tồn tại → trả 404 NODE_NOT_FOUND (không phải 409), khó phân biệt với gõ sai id.
  • Endpoint neighbors (Node Detail) KHÔNG lọc theo profile — duyệt MỌI loại cạnh [rels*1..h], cap 50/chiều; và không loại self-loop (node có thể tự xuất hiện trong incoming/outgoing).

Luồng hoạt động của code

  • UI: ImpactAnalysisPanel.vue — 2 <select> (profile/depth) + nút Analyze; watcher reset khi đổi depth/profile/node; render risk badge + nhóm.
  • Composable: useImpactAnalysis.ts validate depth ∈ {1,2,3,5} & profile ∈ {dependency,structural,type-data-flow}, gọi graphApi.getImpact, giữ token chống race.
  • HTTP: GET /api/projects/{id}/graph/impact?nodeId=&depth=&profile=.
  • Backend: GraphController.getImpactAnalysis() → Neo4jGraphRepository: truy vấn theo ImpactProfile.relationshipPattern() & directedToTarget(), gom node theo depth (byDepth 1/2/≥3), đếm (countsByDepth), tính riskLevel(directDependents).
  • Điều hướng: click node ảnh hưởng → GraphCanvas.onImpactSelect → selectNode + focusNode.
  • Song song MCP: tool get_impact_analysis (ImpactAnalysisAnalyzerImpl) trả cùng dữ liệu (có cap MAX_DIRECT/MAX_TRANSITIVE) cho AI agent.
