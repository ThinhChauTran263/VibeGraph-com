Neo4j — Cơ sở dữ liệu đồ thị

Neo4j là nơi VibeGraph lưu toàn bộ đồ thị mã nguồn (node = phần tử code, cạnh = quan hệ). Mọi tính năng Graph / Impact / Flows / Diagrams / MCP đều truy vấn dữ liệu từ đây. File này giải thích Neo4j là gì, khác các CSDL khác chỗ nào, và vì sao dự án chọn nó.

Neo4j là gì

  • CSDL đồ thị (graph database) theo mô hình property graph: dữ liệu là node (có nhãn/label + thuộc tính) và relationship (có kiểu + hướng + thuộc tính) nối các node.
  • Quan hệ là công dân hạng nhất: được lưu như con trỏ trực tiếp giữa 2 node (gọi là index-free adjacency), không phải suy ra bằng phép nối như CSDL quan hệ.
  • Truy vấn bằng ngôn ngữ Cypher — cú pháp "vẽ hình" mẫu quan hệ, ví dụ: MATCH (a:Class)-[:CALLS]->(b:Method) RETURN b.
  • Kết nối qua giao thức Bolt (mặc định cổng 7687); có UI quản trị ở 7474.

Khác gì các loại CSDL khác

LoạiVí dụLưu quan hệ thế nàoĐiểm yếu với bài toán "đồ thị code"

Đồ thịNeo4jCon trỏ trực tiếp node↔nodeĐúng bài: mỗi bước nhảy quan hệ gần như O(1), không phụ thuộc tổng kích thước bảng.

Điểm mấu chốt: với CSDL quan hệ, truy vấn càng nhiều "hop" thì càng nhiều JOIN → chi phí tăng nhanh. Neo4j đi theo con trỏ quan hệ nên traversal sâu/độ dài thay đổi (đúng thứ Impact Analysis cần: [:CALLS*1..5]) là thế mạnh cốt lõi.

Cypher vs SQL (cùng câu hỏi "ai phụ thuộc OrderService")

-- Neo4j (Cypher): đường đi 1..3 hop, 1 dòng
MATCH (dep)-[:CALLS|IMPORTS|EXTENDS|IMPLEMENTS|INJECTS*1..3]->(t {fullName:'...OrderService'})
RETURN DISTINCT dep

-- SQL tương đương: phải dùng recursive CTE + tự join bảng cạnh, dài & chậm hơn.

Vai trò trong VibeGraph

Neo4j là "nguồn sự thật" duy nhất cho đồ thị mã nguồn. Parser đọc code Java → sinh danh sách node/edge → ghi vào Neo4j. Từ đó mọi API và tính năng phía trên đều đọc lại từ Neo4j. Toàn bộ đại số truy vấn nằm trong Neo4jGraphRepository.java.

Vài cơ chế "ruột" cần biết khi review

  • Danh tính node = {projectId, fullName} (không dùng id() nội bộ của Neo4j). Lý do: id() bị tái sử dụng sau khi xoá và đổi qua mỗi lần phân tích lại → không ổn định cho hợp đồng BE↔FE. Xem stableNodeId().
  • MERGE = upsert. upsertNodes MERGE không kèm label theo {projectId, fullName}, rồi mới SET n:<Label> và REMOVE n:External. Nhờ vậy khi phân tích lại, một node "stub" External (tạo tạm cho tham chiếu chưa resolve) được làm giàu thành node thật thay vì tạo trùng.
  • Cạnh không bao giờ bị bỏ. upsertEdges nếu chưa thấy 2 đầu thì MERGE ... ON CREATE SET a:External — mọi tham chiếu tới thư viện/JDK/đích chưa parse đều thành node External.
  • Không parameter hoá được label/rel-type trong Cypher → code phải gom theo label / theo loại quan hệ rồi chạy 1 batch UNWIND mỗi nhóm (chuỗi label/type được nội suy vào câu Cypher sau khi đã validate qua GraphSchema).
  • Xoá là DETACH DELETE — xoá node kèm mọi cạnh dính vào nó (Neo4j không cho xoá node còn cạnh).
  • Full-text index node_search phục vụ ô tìm kiếm; kết quả vẫn phải lọc lại WHERE node.projectId = $projectId ở tầng Cypher.
  • Chống rò rỉ chéo project: mọi truy vấn traversal đều ràng all(node IN nodes(path) WHERE node.projectId = $projectId) để đường đi không "nhảy" sang project khác.

Điểm reviewer cần soi

  • Một DB dùng chung, tách project chỉ bằng thuộc tính projectId — chưa có ownerId. Nếu deploy đa người dùng mà không thêm lọc theo chủ sở hữu thì user A có thể đọc project user B (xem roadmap bảo mật). Đây là vấn đề multi-tenant, không phải bug của Neo4j.
  • Mỗi session.run là một transaction auto-commit riêng. Import nhiều batch = nhiều tx tách rời, không bọc trong 1 managed transaction → nếu lỗi giữa chừng, dữ liệu đã ghi không tự rollback về trạng thái sạch.
  • Phải có Neo4j sống trước. Backend chạy migration schema lúc khởi động; Neo4j (Docker) chưa READY → backend tắt ngay. Reviewer nhớ docker start vibegraph-neo4j trước.
  • Giới hạn hiển thị: Node Detail tối đa 50 connection, Impact tối đa 50 node mỗi bậc (MAX_DETAIL_CONNECTIONS, MAX_IMPACT_NODES_PER_DEPTH) — con số đếm (totalDependents) vẫn đầy đủ, chỉ danh sách trả về bị cắt.
  • Độ sâu bị chốt whitelist {1,2,3,5} (validateImpactDepth) — tránh traversal vô hạn làm nặng DB.
