As-Built Use Case Diagram

Điểm khác biệt lõi của VibeGraph: sinh sơ đồ Use Case từ mã đã build. Pipeline backend: UseCaseInferenceEngine.infer → BaLabelBeautifier → GenericRelationInferer (include) → UseCaseSemanticRefiner (Tier-2 LLM) → renderer → UseCaseViewProjector (views theo actor/domain).

① Suy luận ACTOR (inferActor) — theo độ mạnh tín hiệu

NguồnĐiều kiệnActorConf
Role (mạnh nhất)requiredRole chứa ADMIN/SUPERUSER/ROOTAdmin0.95

HTTP method KHÔNG dùng để đoán Admin. Guest chỉ tạo khi có register/login và chỉ nối tới goal "Register account"/"Log in" (không có generalization User→Guest). requiredRole đến từ parser (@PreAuthorize/@Secured/@RolesAllowed).

② Suy luận USE CASE (goal) & gom domain

  • Auth split: path/controller chứa register|signup → REGISTER, login|signin → LOGIN (thành goal của Guest).
  • Domain (inferDomainGuess): từ tên controller (regex + strip tech/role words, singularize) conf 0.9; else segment path đầu (bỏ api/v#/admin/auth) conf 0.6; else "Resource" conf 0.3.
  • Manage vs View: manage = adminScoped || (writeRatio ≥ 0.25 && mutatingCount > 0). Domain báo cáo (analytic/dashboard/report/audit/metric…) giữ "View" trừ khi có write. Tên = verb + pluralName.
  • View page routes: node prop view=true & non-mutating → bỏ (presentation). Form POST view → giữ.
  • Loại trừ: /actuator, /error, /swagger-ui, /v3/api-docs, /static, /assets, /debug, /internal, SPA screen routes, "/", "/home"…
  • Dedup/scope: gộp use case cùng label; khi trùng thêm " (All)" (admin) / " (Own)" (non-admin); thêm Admin --|> User và bỏ association Admin dư mà User đã có.

③ Fallback nhiều tầng (không có endpoint) — inferDomainsFromClasses

Kích hoạt khi domains rỗng && không register/login. Tầng đầu tiên có dữ liệu thắng:

TầngConfGhi chú
service0.75method public, bỏ noise
controller0.7—
entity0.5bỏ accessor get/set/is; entity trơ → luôn "Manage X"
generic0.4class có business method

Actor fallback: tên bắt đầu "admin" → Admin, else User; tất cả guessed=true. Nếu không có class đủ điều kiện → vẫn rỗng + warning "No business use cases…".

④ Include («include») — GenericRelationInferer

Đề xuất «include» CHỈ khi thoả cả 3:

  • Service được ≥ 2 use case (base) khác nhau dùng chung (MIN_SHARING_USE_CASES=2), tính từ cạnh INJECTS controller→service.
  • KHÔNG phải infra-service & LÀ business-service (allowlist: validat/authentic/authoriz/notif/email/payment/billing/invoic/calculat/pricing/tax/audit/search/report/export/import/schedul/discount/inventory/shipping/delivery).
  • Có nhãn capability (map CAPABILITY_VERB, vd payment→"Process Payment").
Nguyên tắc "không bịa": «extend» KHÔNG bao giờ được suy (không thể phục hồi luồng optional/conditional từ phân tích tĩnh). Giới hạn này hiển thị thành warning.

⑤ Views theo actor/domain (UseCaseViewProjector)

Là sub-graph induced của model chính (không re-infer → không thể lệch với sơ đồ đầy đủ). Actor view = actor + tổ tiên generalization + use case liên quan + expandIncludes (fixpoint). Domain view = use case cùng domain (bỏ bucket "shared") + include + actor.

⑥ Tier-2 LLM refine (mặc định TẮT)

  • Bật khi vibegraph.usecase.llm.enabled=true + có ChatModel khả dụng; else NoopUseCaseRefiner (identity).
  • Chỉ relabel: gửi fact JSON (id/name/domain, KHÔNG source code); prompt strict KEEP; chỉ đổi nhãn id đã có, không thêm/bớt node/relation. Id ảo bị bỏ. Cache theo SHA-256.
  • Lỗi/timeout/rỗng → giữ nguyên input (fallback deterministic).
⚠ Ngóc ngách reviewer cần biết:
  • roleGuessed warning bật khi bất kỳ endpoint rơi vào default User (0.7) → dễ over-warn ngay cả khi đa số role đã chứng minh.
  • Auth split & exclude dùng substring → false positive (vd /users/loginHistory bị coi là Login).
  • Actor business role (Seller, Courier…) không generalization về User → nổi độc lập.
  • FE umlUseCaseSvg.isExternalSystem: actor tên chứa system/service/gateway/api/server/provider/platform bị vẽ như external system (vd "Service Manager" hiển thị sai).
  • Phần tử confidence < FAINT_THRESHOLD 0.6 (vd include 0.5) render mờ/nét đứt — đánh dấu là suy luận.
  • "Mode" (flat/summary…) hầu như cosmetic: model không đổi theo mode.
