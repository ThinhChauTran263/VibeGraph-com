Graph Model — Cách dựng đồ thị tri thức

Đây là nền tảng của mọi tính năng (Graph, Impact, Flows, Diagrams, MCP). Hiểu node/edge nào được sinh ra và điều kiện giúp review chuẩn: nếu một cạnh thiếu, mọi tính năng phía trên đều lệch theo.

Dành cho người mới / thầy cô hỏi nhanh: đọc mục "Từ điển dễ hiểu" ngay dưới đây (giải thích mỗi loại là gì + ví dụ Java). Muốn biết parser sinh ra chúng khi nào thì đọc tiếp mục "Catalog" ở phần sau (chi tiết kỹ thuật).

Từ điển dễ hiểu — LOẠI NODE (điểm/đốm trên đồ thị)

Node = một "phần tử" trong mã nguồn. Trên panel NODE TYPES, mỗi loại có màu & số đếm riêng. Con số ví dụ dưới đây lấy từ một project mẫu.

Loại nodeLà gì (nói đơn giản)Ví dụ trong code Java
ProjectCả dự án — 1 điểm gốc đại diện toàn bộ codebase (luôn có đúng 1).toàn bộ repo my-app
PackageGói/thư mục Java — nhóm các file cùng nhánh.package com.abc.service;
FileMột tập tin mã nguồn .java.UserService.java
ClassMột lớp — bản thiết kế cho đối tượng.class UserService { }
InterfaceGiao diện — bản hợp đồng liệt kê phương thức, không có phần thân.interface Repository { }
EnumKiểu liệt kê — tập hằng số cố định.enum Status { ON, OFF }
RecordLớp bản ghi — lớp chứa dữ liệu bất biến, viết gọn.record Point(int x, int y) {}
AnnotationChú thích — nhãn gắn lên code để đánh dấu / cấu hình.@Service, @Override
MethodPhương thức (hàm) trong lớp — một hành vi/việc code làm được.public void save() { }
ConstructorHàm khởi tạo — chạy khi tạo đối tượng mới bằng new.public UserService() { }
FieldThuộc tính (biến thành viên) của một lớp.private int age;
APIEndpointMột điểm cuối REST = phương thức HTTP + đường dẫn; là "cửa" client gọi vào backend.GET /api/users
DBModelLớp ánh xạ bảng dữ liệu (có @Entity/@Table/@Node...) — đại diện 1 bảng/collection trong DB.@Entity class User { }
ExternalNode "bên ngoài" — thứ code có nhắc tới nhưng VibeGraph chưa/không phân tích (thư viện, JDK, hoặc chưa resolve). Giữ lại để cạnh không bị mất.String, List, class của thư viện ngoài

Từ điển dễ hiểu — LOẠI EDGE (đường nối giữa 2 node)

Edge = một quan hệ có hướng giữa 2 node. Đọc theo mẫu "A —QUAN HỆ→ B". Trên panel EDGE TYPES mỗi loại cũng có màu & số đếm riêng.

Loại edgeÝ nghĩa (A —quan hệ→ B)Ví dụ
CONTAINSA chứa B (theo cấu trúc thư mục/gói).Package —CONTAINS→ File
DEFINESFile khai báo/định nghĩa phần tử nào bên trong nó.File —DEFINES→ Class
HAS_METHODLớp có phương thức này.Class —HAS_METHOD→ Method
HAS_FIELDLớp có thuộc tính này.Class —HAS_FIELD→ Field
IMPORTSFile dùng nhờ (import) lớp/gói khác.File —IMPORTS→ Class
EXTENDSLớp con kế thừa lớp cha (hoặc interface mở rộng interface).Dog —EXTENDS→ Animal
IMPLEMENTSLớp hiện thực một giao diện.UserServiceImpl —IMPLEMENTS→ UserService
CALLSPhương thức A gọi phương thức B (chỉ khi B nằm trong dự án).save() —CALLS→ validate()
OVERRIDESPhương thức ghi đè phương thức cùng tên ở lớp cha.toString() —OVERRIDES→ Object.toString()
RETURNSPhương thức trả về kiểu dữ liệu gì (bỏ void).getUser() —RETURNS→ User
PARAMETER_TYPEKiểu tham số của phương thức.save(User u) —PARAMETER_TYPE→ User
THROWSPhương thức có thể ném ngoại lệ loại nào.read() —THROWS→ IOException
TYPE_OFKiểu của một thuộc tính (bỏ kiểu nguyên thủy/String).field repo —TYPE_OF→ UserRepository
INSTANTIATESNơi code tạo mới đối tượng bằng new.method —INSTANTIATES→ ArrayList
ANNOTATED_BYPhần tử được gắn annotation nào.UserService —ANNOTATED_BY→ @Service
HANDLES_ROUTEPhương thức xử lý endpoint REST nào.listUsers() —HANDLES_ROUTE→ GET /api/users
INJECTSTiêm phụ thuộc (Spring DI): lớp được "tiêm" một bean khác vào để dùng.UserController —INJECTS→ UserService
STEP_IN_FLOWMột bước trong luồng xử lý (suy luận: từ endpoint đi theo các lời gọi) — dùng dựng Data Flow.controller → service → repository
READS / WRITES / CATCHESPhương thức đọc/ghi một field, hoặc bắt ngoại lệ — chỉ khi bật chế độ phân tích sâu (deep-cpg).save() —WRITES→ field count

Pipeline phân tích

  • Scan: ParserServiceImpl.parseProject quét file .java, dựng 1 parser project-wide với SymbolSolver (Reflection + JavaParserTypeSolver cho mọi source root; phát hiện src/main/java, src/test/java hoặc suy từ package declaration).
  • Per file: chạy 6 visitor (ClassVisitor, MethodVisitor, FieldVisitor, SpringAnnotationVisitor, AnnotationVisitor, ImportVisitor) + tạo node File/Package + cạnh DEFINES/CONTAINS.
  • Aggregate (AnalyzeServiceImpl): gộp toàn project, thêm Project→Package (CONTAINS), chạy FlowAnalyzer.inferStepInFlow, guardrail kích thước, rồi upsert Neo4j.
  • Tiến độ: parse chiếm 5%→70%, 72% quan hệ, 80% lưu node, 94% lưu cạnh, 98% finalize, 100% xong.

Symbol resolution & External

  • SymbolSolver dùng cho CALLS, OVERRIDES, INSTANTIATES. Fail resolve → fallback lexical (imports → same package → java.lang) hoặc bỏ (CALLS/OVERRIDES nuốt im lặng).
  • Type reference (RETURNS/PARAMETER_TYPE/TYPE_OF/EXTENDS/INJECTS) dùng tên lexical; target chưa parse → tạo External stub {projectId, fullName} (MERGE không label, SET label thật khi node được upsert sau).
  • Identity node = {projectId, fullName} (label-agnostic) → upsert node enrich External cùng fullName thay vì tạo trùng.
⚠ Giới hạn & điểm reviewer cần soi (ảnh hưởng độ chính xác chương đánh giá):
  • CALLS chỉ resolved in-project: bỏ hoàn toàn call tới lib/JDK/Spring; recall phụ thuộc mạnh vào source-root detection. parseFile() đơn lẻ (realtime 1 file) gần như không resolve cross-class.
  • INJECTS: setter injection & @Bean factory KHÔNG được nhận diện (gap thật — đây là "Nhóm B" mục #1).
  • Cache parse CHƯA hiện thực: CacheService.java rỗng; mỗi lần analyze parse lại toàn bộ (thư mục .gitnexus/parse-cache là của công cụ ngoài, không phải VibeGraph).
  • INJECTS trùng: FieldVisitor + SpringAnnotationVisitor cùng phát cho field @Autowired → dựa MERGE khử trùng.
  • resolveTypeName lexical fragile: wildcard import → FQCN sai → External sai; generic bị strip.
  • STEP_IN_FLOW ownership: MERGE trên (from)-[type]->(to) không có khoá per-step → 1 call thuộc nhiều flow chỉ 1 edge sống, metadata phản ánh flow đầu tiên.
  • Endpoint annotation vs interface: @RequestMapping không khai method → placeholder "REQUEST".

Guardrail kích thước

AnalyzeServiceImpl fail-fast nếu nodes > VIBEGRAPH_ANALYZE_MAX_NODES (200k) hoặc edges > MAX_EDGES (600k) → IllegalStateException (409). Tầng đọc/serve có cap riêng (payload HTTP 1500/4000; SourceGraphSupport 50k/200k).
