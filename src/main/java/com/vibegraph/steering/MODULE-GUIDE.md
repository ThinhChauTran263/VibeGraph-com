# Module: `steering/` — Auto-Generate AI Steering Files

> **Vai trò:** Tự động sinh file rules cho AI tools mỗi khi project thay đổi: `.kiro/steering/vibegraph-context.md` (Kiro), `.cursor/rules/vibegraph.mdc` (Cursor), `CLAUDE.md` section (Claude Code), `.kiro/hooks/vibegraph-precheck.json` (pre-code hook). File này nằm **trong project được analyze** (không phải project VibeGraph), giúp AI tools đọc context tự động.

> **Dev phụ trách:** Dev 4 (Frontend Dev) — phần Java backend, do task 4.14-4.17 thuộc Sprint 3.

> **Sprint:** Sprint 3 (Week 5-6).

> **Phụ thuộc:** `common/` (FileUtils), `mcp/` (ArchitectureAnalyzer — reuse logic, không duplicate), `graph/` (ProjectService).

---

## Mục tiêu module

1. Generate steering file cho 3 AI tools: Kiro, Cursor, Claude Code (FR-12)
2. Generate pre-code hook template cho Kiro (FR-13)
3. Auto-update khi graph thay đổi (debounced ~5s, không write mỗi file save)
4. KHÔNG overwrite custom rules của user — chỉ append/update VibeGraph section
5. Configurable: user chọn generate cho tool nào (per-project setting)
6. Atomic write — không corrupt file nếu app crash giữa chừng

### `service/impl/SteeringFileServiceImpl.java`
**Mục tiêu:** Orchestrator — phối hợp các writer + ArchitectureAnalyzer.

**Phải làm:**
- `@Service`, inject:
  - `ArchitectureAnalyzer` (từ mcp module — reuse logic detect layers/patterns/rules)
  - `KiroSteeringWriter`, `CursorRulesWriter`, `ClaudeRulesWriter` (qua `Map<SteeringTarget, SteeringWriter>`)
  - `ProjectService`
- Lưu enabled targets per-project: `Map<String, Set<SteeringTarget>>` hoặc persist vào ProjectNode property
- Default enabled: tất cả 4 targets

**Method `generateAll(projectId)`:**
1. Lấy `ProjectNode` từ projectId
2. Build `SteeringContext` 1 lần (re-use cho mọi writer):
   - `architectureAnalyzer.detectLayers(projectId)`
   - `detectPatterns(projectId)`
   - `detectNaming(projectId)`
   - `generateRules(projectId)`
   - `detectWarnings(projectId)`
3. Cho mỗi `SteeringTarget` enabled:
   - Resolve writer từ map
   - Gọi `writer.write(projectRoot, context)`
4. Log: `"Generated steering files for {projectId}: {targets}"`

**Method debounced regeneration:**
- `@EventListener(GraphUpdateEvent.class)`
- Debounce 5s — dùng `ScheduledExecutorService`, cancel + reschedule mỗi event
- Tránh regenerate khi user đang code liên tục

**Đạt được khi:**
- [ ] Sau analyze xong → 4 files được tạo trong project root
- [ ] Edit code → 5s sau steering files được update
- [ ] Concurrent regeneration cho cùng project → debounce, chỉ chạy 1 lần
- [ ] Coverage > 70%

**Tham chiếu:** `requirements.md` FR-12, FR-13; `architecture.md` §9.5; `task-breakdown.md` 4.14-4.17

### `writer/KiroSteeringWriter.java`
**Mục tiêu:** Generate `.kiro/steering/vibegraph-context.md` (markdown với frontmatter).

**Output path:** `{projectRoot}/.kiro/steering/vibegraph-context.md`

**Phải làm:**
- `@Component`, implement `SteeringWriter`
- `getTarget()` return `SteeringTarget.KIRO`
- Method `write`:
  1. Build content theo template (xem mẫu architecture.md §9.5):
     ```markdown
     ---
     inclusion: always
     ---

     # VibeGraph Project Context (auto-generated)
     # Last updated: {timestamp}
     # DO NOT EDIT — this file is regenerated by VibeGraph

     ## Architecture Layers
     {layers list}

     ## Packages
     {packages list with description}

     ## Naming Conventions
     {naming patterns}

     ## Patterns
     {patterns}

     ## Rules
     ### DO
     {do rules}

     ### DON'T
     {dont rules}

     ## Current Warnings
     {warnings}
     ```
  2. Tạo dir `.kiro/steering/` nếu chưa có
  3. **Atomic write**: write to `vibegraph-context.md.tmp`, fsync, rename to final path
  4. Set file permission readable (Unix: 644)
- KHÔNG overwrite các file khác trong `.kiro/steering/` (chỉ ghi `vibegraph-context.md`)

**Đạt được khi:**
- [ ] File generate đúng format frontmatter Kiro yêu cầu
- [ ] Atomic write — không corrupt nếu crash
- [ ] Existing user files trong `.kiro/steering/` không bị động
- [ ] Test: edit demo project → file content khớp expected

**Tham chiếu:** `architecture.md` §9.5 (template), `requirements.md` FR-12

### Hook generator (sub-task của KiroSteeringWriter hoặc class riêng)

**Mục tiêu:** Generate `.kiro/hooks/vibegraph-precheck.json` (FR-13).

**Phải làm:**
- Có thể tách `KiroHookWriter.java` riêng (target = `KIRO_HOOK`) hoặc gộp vào `KiroSteeringWriter`
- Output path: `{projectRoot}/.kiro/hooks/vibegraph-precheck.json`
- Content (xem architecture.md §9.6):
  ```json
  {
    "name": "VibeGraph Architecture Check",
    "version": "1.0.0",
    "description": "Forces AI to read project architecture context before writing code",
    "when": {
      "type": "preToolUse",
      "toolTypes": ["write"]
    },
    "then": {
      "type": "askAgent",
      "prompt": "Before writing this file, verify it follows the project architecture. Check: 1) Correct layer (Controller/Service/Repository), 2) Correct package, 3) Correct naming convention, 4) No anti-patterns from VibeGraph rules. If you haven't read the VibeGraph context yet, call the get_project_architecture MCP tool first."
    }
  }
  ```
- Configurable mode: `strict` (block AI nếu chưa đọc context) vs `advisory` (warn only) — đọc từ ProjectNode property

**Đạt được khi:**
- [ ] File JSON valid, Kiro parse được
- [ ] User chọn mode strict/advisory ảnh hưởng prompt
- [ ] Không overwrite nếu user đã custom (file có flag `vibegraph_managed: false`)

**Tham chiếu:** `architecture.md` §9.6, `requirements.md` FR-13

### `writer/ClaudeRulesWriter.java`
**Mục tiêu:** Generate / update section trong `CLAUDE.md` cho Claude Code.

**Output path:** `{projectRoot}/CLAUDE.md`

**Phải làm:**
- KHÔNG overwrite toàn bộ file — chỉ update section có marker:
  ```markdown
  <!-- VIBEGRAPH:START -->
  ## Project Architecture (auto-generated by VibeGraph)
  Last updated: {timestamp}

  {content}
  <!-- VIBEGRAPH:END -->
  ```
- Logic write:
  1. Đọc CLAUDE.md hiện có (nếu có)
  2. Tìm marker `<!-- VIBEGRAPH:START -->` và `<!-- VIBEGRAPH:END -->`
  3. Nếu có: replace nội dung giữa markers
  4. Nếu không có: append section vào cuối file
  5. Nếu CLAUDE.md không tồn tại: create new file với section
  6. Atomic write
- Dùng regex DOTALL: `<!-- VIBEGRAPH:START -->[\s\S]*?<!-- VIBEGRAPH:END -->`

**Đạt được khi:**
- [ ] Custom rules user viết tay (ngoài markers) **không bị mất**
- [ ] Multiple regenerate → section luôn update đúng vị trí, không duplicate
- [ ] CLAUDE.md không tồn tại → tạo mới với chỉ VibeGraph section
- [ ] Test edge case: file có 2 cặp markers (ngẫu nhiên) → chỉ update cặp đầu tiên + log WARN

**Tham chiếu:** `requirements.md` FR-12 (không overwrite user custom)

## Lưu ý cross-module

- KHÔNG duplicate logic detect architecture — luôn delegate `ArchitectureAnalyzer` (mcp module)
- File output nằm **trong project được analyze**, KHÔNG nằm trong VibeGraph backend → cần permission write project directory
- Validate path: phải nằm dưới `projectRoot`, không được escape ra ngoài (security: tránh path traversal)
- Listener subscribe `GraphUpdateEvent` từ graph module — schedule debounce
- Lưu generated timestamp trong file content + ProjectNode property `lastSteeringGenAt` để debug
- Nếu nhiều VibeGraph instance cùng analyze 1 project (rare) → file lock optional, hoặc warning trong README "1 project chỉ nên có 1 instance watch"
- Tested writers nên có sample project fixture trong `src/test/resources/sample-project/` để verify output thật
- Khi user xóa project khỏi VibeGraph → KHÔNG tự xóa file steering (giữ lại cho tới khi user tự dọn) — tránh làm mất rule custom họ đã merge
