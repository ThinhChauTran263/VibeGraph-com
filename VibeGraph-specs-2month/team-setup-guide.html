01 Yêu cầu

1. Yêu cầu máy dev

Bắt buộc nếu chạy Docker

  • Git
  • Docker Desktop hoặc Docker Engine có Docker Compose v2
  • Port trong máy còn trống: 3000, 8080, 7474, 7687

Bắt buộc nếu chạy local dev

  • Java 21
  • Node.js 20.19+ hoặc 22.12+
  • Docker để chạy Neo4j local
  • Maven không bắt buộc nếu dùng mvnw/mvnw.cmd

Khuyến nghị cho team: dùng Docker Compose trước để có Neo4j + backend + frontend cùng lúc. Local dev tách riêng chỉ dùng khi cần sửa code backend/frontend.

04 Database

4. Neo4j database và cách kiểm tra

Neo4j được chạy bằng service neo4j trong docker-compose.yml.

Thông tinGiá trị mặc định
HTTP Browserhttp://localhost:7474
Bolt URIbolt://localhost:7687
Usernameneo4j
Passwordvibegraph
Docker volumeneo4j-data, neo4j-logs

Có cần chạy file init để import database không?

Không cần. Khác với SQL (phải import init.sql thủ công), VibeGraph tạo schema tự động. Khi backend khởi động, Neo4jMigrationRunner đọc và chạy file src/main/resources/db/migration/V1__init_schema.cypher. Bạn chỉ cần chạy backend (qua Docker Compose hoặc local) là schema được áp dụng.

Cách hiểu nhanh nếu quen với MySQL:

Bên SQLBên VibeGraph (Neo4j)Chạy lúc nào
init.sql — CREATE TABLE, INDEX, FKV1__init_schema.cypher — constraints + indexesTự động khi backend startup (không chạy tay)
INSERT data / import dumpChạy analyze project — parser sinh node/relationshipKhi bạn gọi POST /api/projects/PROJECT_ID/analyze (xem mục 5)

File V1__init_schema.cypher không chứa data — chỉ có constraints và indexes (giống phần DDL của init.sql). Mọi statement đều dùng IF NOT EXISTS nên chạy lại nhiều lần vẫn an toàn.

Nếu muốn chạy file schema thủ công (tùy chọn)

Bình thường không cần, vì backend đã tự chạy. Chỉ dùng khi muốn áp schema vào một Neo4j trống mà chưa chạy backend. Chạy bằng cypher-shell trong container Neo4j:

bash
# Đẩy file cypher vào container rồi chạy bằng cypher-shell
docker compose cp src/main/resources/db/migration/V1__init_schema.cypher neo4j:/tmp/init.cypher
docker compose exec neo4j cypher-shell -u neo4j -p vibegraph -f /tmp/init.cypher

Trên Docker Compose v2 cũ có thể dùng docker cp / docker exec với tên container vibegraph-neo4j thay cho docker compose cp/exec.

Cypher kiểm tra nhanh trong Neo4j Browser

cypher
SHOW CONSTRAINTS;
SHOW INDEXES;
MATCH (n) RETURN labels(n) AS labels, count(*) AS count ORDER BY count DESC;
05 Smoke test

5. Smoke test nhanh sau khi chạy

Sau khi backend và Neo4j đã lên, có thể test API bằng PowerShell.

Flow mới: upload ZIP/TAR project

Quyết định product ngày 2026-05-31: user sẽ chọn file .zip/.tar/.tar.gz của project Java từ file explorer, bấm Add, backend parse archive rồi mở graph. Flow này thay cho việc nhập local path thủ công.

Trạng thái hiện tại: endpoint POST /api/projects/import-archive chưa implement. Cho tới khi Sprint 2 hoàn tất task này, smoke test nội bộ vẫn phải dùng legacy local-path flow bên dưới để kiểm chứng parser/Neo4j/graph render.

target api
POST /api/projects/import-archive
Content-Type: multipart/form-data

name = sample-java
file = sample-java.zip

Legacy fallback hiện tại: đăng ký local path

Chỉ dùng tạm cho dev/internal smoke test trước khi archive upload được implement.

powershell
# Body khi project nằm trong ./projects/sample-java và được mount thành /projects/sample-java
$body = @{ name = "sample-java"; rootPath = "/projects/sample-java" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/projects -ContentType "application/json" -Body $body

Chạy analyze và lấy graph

powershell
# Thay PROJECT_ID bằng id trả về ở bước đăng ký
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/projects/PROJECT_ID/analyze -ContentType "application/json" -Body "{}"
Invoke-RestMethod -Method Get -Uri http://localhost:8080/api/projects/PROJECT_ID/graph

Sau khi archive upload hoàn tất, phần local-path fallback này không còn là UX chính cho user.

06 Bàn giao

6. Cần copy/gửi những file nào cho team

Khuyến nghị tốt nhất: không copy từng file. Hãy merge poc vào develop, rồi gửi team link repo + branch develop. Git sẽ đảm bảo không thiếu file, không sai line ending, không mất file ẩn.

Nếu team clone bằng Git

bash
git clone https://github.com/ThinhChauTran263/VibeGraph-com.git
cd VibeGraph-com
git checkout develop
Copy-Item .env.example .env
docker compose up -d --build

Chỉ cần gửi riêng file bị Git ignore

Quan trọng: hầu hết file đã được commit trong repo nên clone về là có sẵn — không cần gửi tay. Chỉ những file nằm trong .gitignore mới thật sự cần gửi riêng. Theo .gitignore hiện tại, đó là .env (và token nếu có).

Bảng dưới đây phân biệt rõ file nào đã ở trong Git và file nào phải gửi riêng:

File/cấu hìnhTrạng tháiGhi chú
.envGửi riêngBị .gitignore chặn nên clone về không có. Gửi riêng cho team, hoặc để team tự copy từ .env.example. Chỉ chứa local/dev values như NEO4J_USERNAME=neo4j, NEO4J_PASSWORD=vibegraph, NEO4J_URI=bolt://localhost:7687, FRONTEND_URL=http://localhost:3000. Không đưa production secrets vào file gửi chung.
Secrets thật (GITHUB_TOKEN, password prod...)Gửi riêngKhông commit, không đặt vào .env gửi chung. Chỉ gửi khi cần (ví dụ test GitHub import) qua kênh secret/password manager.
docker-compose.ymlCó trong GitĐã commit, clone là có. Không cần gửi riêng.
Project mẫu dạng .zip/.tar/.tar.gzGửi riêng nếu cần demoĐây là artifact đúng với flow product mới: user upload archive thay vì nhập local path.
VibeGraph-specs-2month/team-setup-guide.htmlCó trong GitFile hướng dẫn này, đã nằm trong repo.

Nếu bắt buộc gửi file ZIP nội bộ

Hãy zip từ thư mục gốc repo và bao gồm các file/folder sau:

Cần gửiVì sao cần

vibegraph-web/Frontend Vue/Vite và Dockerfile frontend

Không nên gửi

  • target/ — build output backend
  • vibegraph-web/node_modules/ — dependency frontend, cài lại bằng npm ci
  • vibegraph-web/dist/ — build output frontend
  • .env có production secret, token cá nhân, password thật — chỉ gửi .env local/dev nếu team thống nhất dùng chung credential dev
  • .git/ nếu chỉ gửi source zip
  • .idea/, .vscode/ — setting cá nhân IDE
  • neo4j-data/ hoặc Docker volumes — data local

Lệnh tạo ZIP trên Windows PowerShell

powershell
# Chạy từ thư mục cha của repo, không phải bên trong repo
Compress-Archive -Path .\VibeGraph-com\src, .\VibeGraph-com\vibegraph-web, .\VibeGraph-com\VibeGraph-specs-2month, .\VibeGraph-com\pom.xml, .\VibeGraph-com\mvnw, .\VibeGraph-com\mvnw.cmd, .\VibeGraph-com\.mvn, .\VibeGraph-com\Dockerfile, .\VibeGraph-com\docker-compose.yml, .\VibeGraph-com\.env.example, .\VibeGraph-com\README.md -DestinationPath .\VibeGraph-com-team.zip -Force

Nếu repo của team có RULES.md/AGENTS.md ở root, thêm chúng vào lệnh zip.

07 Trạng thái

7. Trạng thái hiện tại cần nói rõ với team

Các mục dưới đây giúp team không hiểu nhầm là Sprint 1 đã xong toàn bộ MVP.

  • CóLocal vertical slice: register project → analyze → Neo4j → GET graph → Sigma render.
  • Một phầnParser có Class/Method/Field/Route/CALLS resolved in-project, nhưng chưa đầy đủ schema target.
  • Chưa xongGitHub import hiện có route/service contract, implementation còn not implemented.
  • Chưa xongWatcher/realtime: endpoint STOMP có, broadcast/client/watch pipeline còn TODO.
  • Chưa xongDiagram và MCP tools đang ở mức scaffold.
  • Cần làmPublic demo cần auth/rate-limit/path validation/actuator hardening trước khi expose.

8. Lỗi hay gặp

bash

bash

bash

Kiểm tra .env có NEO4J_USERNAME=neo4j và NEO4J_PASSWORD=vibegraph. Khi chạy backend local, cần set NEO4J_URI=bolt://localhost:7687.

powershell
cd vibegraph-web
Remove-Item -Recurse -Force node_modules
npm ci

bash
